你现在是一个资深图形程序员与创意编码工程师。

请为 M5StickS3（ESP32-S3）实现一个“毒液寄生体”电子宠物。

# 项目目标

在 240x135 LCD 屏幕中实现一个：
- 黑色
- 粘稠
- 会变形
- 会贴边爬行
- 有一只眼睛
- 像“活着的毒液”

的实时程序动画生命体。

整体风格参考：
- Venom（毒液）
- 黑色液态共生体
- 石油/沥青飞溅
- Gooey / Metaball 生物

重点：
不是卡通宠物。
而是“屏幕里寄生着某种液态生物”。

-----------------------------------
# 硬件平台
-----------------------------------

设备：
M5StickS3 / ESP32-S3

屏幕：
240x135 TFT LCD

开发环境：
Arduino Framework

图形库：
优先使用 TFT_eSPI 或 M5Unified

目标帧率：
15~30 FPS

要求：
必须在 ESP32-S3 上实时运行。

-----------------------------------
# 技术路线（非常重要）
-----------------------------------

不要使用：
- sprite sheet
- GIF动画
- 固定帧动画
- 大量PNG素材

必须使用：
# 程序化实时生成动画

核心方案：
# 骨架驱动 Metaball

架构：

AI状态机
    ↓
骨架节点运动
    ↓
Metaball场生成
    ↓
阈值轮廓
    ↓
渲染
    ↓
附加触手与眼睛

-----------------------------------
# Metaball实现要求
-----------------------------------

实现真正的 metaball 效果。

使用：
# 低分辨率标量场

建议：
60x34
或
80x45

然后放大到屏幕。

不要全分辨率逐像素计算。

-----------------------------------
# 场函数
-----------------------------------

使用类似：

field += radius² / distance²

或类似 metaball influence 算法。

最终：

field > threshold

则认为属于生物区域。

-----------------------------------
# 渲染方式
-----------------------------------

不要抗锯齿。
不要高精度边缘。

允许：
- 粗糙边缘
- 轻微锯齿
- 不稳定轮廓

因为这更像“毒液”。

渲染风格：
- 黑色主体
- 深灰高光（可选）
- 局部尖刺
- 拉丝感
- 不规则边缘

-----------------------------------
# 生物结构
-----------------------------------

生物由多个主 metaball 构成：

建议：
- head ball
- body ball
- tail ball

数量：
3~6个主球即可。

这些球不是随机运动。

必须由：
# 骨架系统
控制。

-----------------------------------
# 骨架系统
-----------------------------------

实现一个简单骨架：

struct Node {
    float x;
    float y;
    float vx;
    float vy;
};

节点之间：
- 有弹性
- 有阻尼
- 有跟随关系

形成：
- 头部
- 身体
- 尾部

要求：
运动必须有“生物感”。

不要：
- 完全随机抖动
- 布朗运动

而是：
- 缓慢拉伸
- 延迟跟随
- 软体惯性
- 呼吸感

-----------------------------------
# 边缘吸附系统
-----------------------------------

毒液必须会：
- 贴屏幕边缘
- 沿边缘爬行
- 吸附在角落
- 从边缘垂下来

实现：
# 边缘吸附力

例如：
靠近边缘时：
- 自动产生吸引
- 身体向边缘拉伸
- 局部metaball固定

效果类似：
“液态生物粘在玻璃上”。

-----------------------------------
# 触手系统
-----------------------------------

不要用粒子流体做触手。

使用：
# 贝塞尔曲线触手

触手特点：
- 黑色
- 有粘性
- 会轻微摆动
- 偶尔伸出又收回

触手连接：
- 生物主体
- 屏幕边缘

要求：
低计算量。

-----------------------------------
# 眼睛系统（重点）
-----------------------------------

眼睛是整个角色灵魂。

实现：
- 一个白色眼睛
- 黑色瞳孔

要求：
# 瞳孔有惯性

不要立即跟随目标。

而是：
target -> damping -> pupil

这样会产生：
- 思考感
- 观察感
- 生物感

-----------------------------------
# 行为状态机
-----------------------------------

实现基础AI状态：

1. idle
- 缓慢呼吸
- 微弱形变

2. crawl
- 沿边缘移动
- 身体拉伸

3. observe
- 眼睛盯住某方向
- 身体轻微前探

4. sleep
- 缓慢脉动
- 触手下垂

5. startled
- 快速收缩
- 局部尖刺增加

状态切换：
使用随机时间与环境事件。

-----------------------------------
# 动画节奏要求（非常重要）
-----------------------------------

不要“持续乱动”。

而是：
- 停顿
- 观察
- 缓慢移动
- 突然收缩
- 轻微抽动

让它像：
“有意识的生物”。

-----------------------------------
# 性能要求
-----------------------------------

必须适配 ESP32-S3。

优化要求：

1.
不要全屏频繁 clear。

2.
尽量局部刷新。

3.
不要动态内存频繁分配。

4.
避免浮点开销过大。

5.
metaball场分辨率低于屏幕。

6.
尽量减少 per-pixel 计算。

-----------------------------------
# 代码结构要求
-----------------------------------

请拆分：

- MetaballSystem
- CreatureAI
- SkeletonSystem
- TentacleRenderer
- EyeSystem
- Renderer

保持模块化。

4.

5.
后续扩展建议

-----------------------------------

最终效果不是：
“Q版电子宠物”。

而是：

“一个寄生在屏幕里的液态共生体”。

用户应该感觉：
它是活的。
